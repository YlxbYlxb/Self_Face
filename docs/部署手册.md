# SelfFace 部署上线手册

从「什么都没有」到「浏览器能打开」，按顺序走完这一份就够了。

整体分三个阶段，**关键是要理解它们的先后关系**：

| 阶段 | 你要做的事 | 能访问的地址 |
|---|---|---|
| ① 买服务器 + 部署 | 买机器、跑部署脚本 | `http://IP:8090` |
| ② 备案（可选但强烈建议） | 买域名、提交备案，等 2~3 周 | 同上（**这一步域名千万别解析过去**） |
| ③ 切域名 + HTTPS | 改两个配置、重跑一条命令 | `https://你的域名` |

备案不用等服务器买好才想，但**备案期间域名不能解析到大陆服务器** —— 这是新手最容易踩的坑，会导致备案被驳回甚至域名被阻断。所以第 ② 阶段什么都不用做，只用 IP 访问就行。

---

## 阶段 ①：买服务器并部署

### 1. 选服务器

SelfFace 的资源占用不大（一个 Spring Boot + 一个 Nginx + 一个 MySQL），配置要求不高：

| 项 | 建议 | 说明 |
|---|---|---|
| CPU / 内存 | **2 核 2G 起步** | 3G 以上构建会快很多；2G 也能跑，脚本会自动补 swap |
| 硬盘 | 40GB SSD | Docker 镜像 + 数据库，40GB 够用很久 |
| 带宽 | 3~5M | 5M 打开页面明显更快 |
| 系统 | **Ubuntu 22.04 / 24.04 LTS** | 本手册以 Ubuntu 为例；Debian / CentOS 也能用，脚本会自动适配 |
| 地域 | 离你/面试官近的国内节点 | 华东、华南、华北都行。**别选香港等海外节点**，那样无法备案 |

**关于学生优惠**：阿里云「云翼计划」和腾讯云「校园计划」都有学生机，2核2G 一般在 **百元以内/年** 的量级，需要学信网认证。价格和活动变动频繁，以官网实时页面为准 —— 直接在官网搜「学生服务器」进专属页面，别去第三方代购。

⚠️ 两个常被忽略的点：
- 学生优惠通常会**限制续费次数或续费涨价**，买之前看清楚续费政策
- 买服务器时如果在活动页看到「赠送域名/备案服务」，直接用

### 2. 记下两个信息

买完后在控制台找到：

- **公网 IP**（形如 `123.45.67.89`）
- **root 密码**（首次可能需要在控制台重置一次）

### 3. 连上服务器

Windows 上打开 PowerShell 或 Git Bash：

```bash
ssh root@你的公网IP
```

第一次会问 `Are you sure you want to continue connecting?`，输 `yes`。然后输密码（输密码时屏幕不显示是正常的）。

### 4. 拉代码

```bash
git clone https://github.com/YlxbYlxb/Self_Face.git /opt/selfface
```

> **如果这一步很慢或者卡住**（国内服务器连 GitHub 有时不稳定），看下面「附录 A：服务器拉不到代码怎么办」。

### 5. 一键部署

```bash
cd /opt/selfface && sudo bash deploy/deploy.sh
```

脚本会自动做完这些事，你只需要等：

- 装 Docker（约 1~3 分钟）
- 配置国内镜像加速（否则拉镜像会超时）
- 内存小于 4G 时自动补 2GB swap，并改成串行构建
- 生成 `.env` 并随机填入三个密钥
- 构建并启动三个容器（后端 / 前端 / MySQL）

**首次构建要 8~15 分钟**（2核2G 的机器），中间会长时间停在 `Downloading` 或 `Compiling`，这是正常的，不要中断。

看到这段就成功了：

```
============================================================
  SelfFace 已启动
    本机：  http://127.0.0.1:8090
    外网：  http://123.45.67.89:8090
============================================================
```

### 6. 放行端口（**不做这步外网打不开**）

云服务器默认只开 22 端口，必须手动放行 8090：

- **腾讯云轻量应用服务器**：服务器详情 → 防火墙 → 添加规则 → 应用类型选「自定义」→ 协议 `TCP` → 端口 `8090`
- **阿里云轻量应用服务器**：服务器详情 → 防火墙 → 添加规则 → `TCP` / `8090`
- **阿里云 ECS**：安全组 → 配置规则 → 入方向 → 添加 `TCP` / `8090`

放行后浏览器打开 `http://你的公网IP:8090`，应该能看到登录页。

### 7. 注册第一个账号

点「立即注册」建号，然后用同一个账号登录。

**注意**：这个站是给你自己用的，没有做邮箱验证之类的限制，所以别把地址到处发 —— 任何人都能注册并消耗服务器资源。

## 阶段 ②：备案（想用域名就必须做）

> 只想用 `IP:8090` 访问的话，可以跳过这一阶段。但简历上写一个 IP 地址不如写域名好看，而且 HTTPS 需要域名。

### 1. 买域名

在买服务器的那家云厂商买最省事（备案流程会打通）：

- `.com` 约 60~80 元/年
- `.top` / `.xyz` / `.cn` 首年常有个位数到十几元的活动价
- 建议选和你名字/项目相关的，比如 `selfface.top`

### 2. 提交备案

在云厂商控制台找「备案」入口，跟着向导走。需要准备：

| 材料 | 说明 |
|---|---|
| 身份证 | 正反面照片 |
| 域名证书 | 控制台可下载 |
| 网站名称 | **个人站建议用中性名称**，别含「博客」「论坛」「资讯」「中国」等词，这些需要前置审批，会被驳回 |
| 服务器实例 | 必须在有效期内，多数厂商要求剩 3 个月以上 |
| 手持身份证照 / 视频核验 | 部分省份要求，按提示做 |

**审核周期约 2~3 周**（云厂商初审 1~2 天 + 管局审核 10~20 天）。

⚠️ **备案期间域名绝对不要解析到大陆服务器**：
- 解析了会在备案审核时被查出，直接驳回
- 更严重的是可能触发「未备案网站阻断」，域名被拉黑一段时间
- 这段时间就用 `http://IP:8090` 访问，完全不影响你刷题

### 3. 拿到备案号

通过后会下发备案号，形如 `京ICP备2026000000号-1`。记下来，阶段 ③ 要用。

## 阶段 ③：切域名 + HTTPS

备案通过后再做这一步。Caddy 会自动申请并续期免费证书（Let's Encrypt），不用手工碰证书文件。

### 1. 域名解析

在云厂商的 DNS 控制台加一条记录：

| 记录类型 | 主机记录 | 记录值 |
|---|---|---|
| A | `@` | 你的服务器公网 IP |
| A | `www` | 你的服务器公网 IP（可选） |

等几分钟生效，用 `ping 你的域名` 确认解析到的是服务器 IP。

### 2. 填两个配置

在服务器上编辑 `.env`：

```bash
cd /opt/selfface && nano .env
```

找到这两行填上：

```ini
APP_DOMAIN=你的域名.com
ICP_BEIAN=京ICP备2026000000号-1
```

- `APP_DOMAIN` 只写域名，**不要带 `http://`**，也不要带路径
- `ICP_BEIAN` 留空的话页面底部就不显示备案信息；填了会按工信部要求展示并链接到备案系统
- 备案号是构建期变量，必须重新构建前端才生效（下面那行命令已经包含了 `--build`）

### 3. 启动 HTTPS 层

```bash
cd /opt/selfface && docker compose --profile tls up -d --build
```

这会多起一个 Caddy 容器，监听 80/443，自动申请证书并把流量分发给前后端。

### 4. 放行 80 / 443

回到云厂商控制台，把 `TCP 80` 和 `TCP 443` 也加进防火墙 / 安全组。

证书签发需要 80 端口可访问，**放行之前 Caddy 拿不到证书**。

### 5. 验证

浏览器打开 `https://你的域名`，应该能看到登录页，地址栏有小锁。

看证书状态：

```bash
docker compose logs caddy | tail -30
```

看到 `certificate obtained successfully` 就是成功。

### 6.（建议）收紧端口

HTTPS 通了以后，把安全组里的 `8090` 规则删掉，只留 22 / 80 / 443。

这样所有流量都必须经过 Caddy，否则别人可以绕过 HTTPS 直接访问 8090（后端限流虽然不会因此失效，但少一个入口更干净）。

## 日常运维

所有命令都在项目目录执行（`cd /opt/selfface`）：

```bash
# 查看容器状态
docker compose ps

# 跟踪日志
docker compose logs -f backend
docker compose logs -f caddy      # HTTPS 证书相关
docker compose logs --tail=100 mysql

# 重启单个服务
docker compose restart backend

# 停止（数据保留在数据卷里）
docker compose down

# 更新到最新代码并重启
sudo bash deploy/update.sh
```

### 备份数据库

```bash
cd /opt/selfface
docker compose exec -T mysql sh -c \
  'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 selfface' \
  > ~/selfface-backup-$(date +%F).sql
```

建议每月跑一次，把文件下载到本地存着。

### 更新代码

```bash
cd /opt/selfface && sudo bash deploy/update.sh
```

脚本会自动拉代码、重新构建、重启，并清理悬空镜像（不清的话旧镜像会慢慢把磁盘吃满）。

## 排错

| 现象 | 原因与处理 |
|---|---|
| 浏览器打不开，`curl` 服务器本机能通 | 安全组没放行 8090，见阶段 ① 第 6 步 |
| 部署卡在 `Pulling` / `Downloading` 超时 | 镜像加速没生效。检查 `/etc/docker/daemon.json`，改完 `systemctl restart docker` |
| 构建中途失败且无明确报错 | 内存不足被 OOM Killer 杀了。`dmesg \| tail` 能看到 `Killed process`。加 swap 或升配后重跑 |
| `docker compose ps` 里 backend 一直`Restarting` | 看 `docker compose logs backend`。最常见是 `.env` 三个密钥没填全 |
| 页面能打开但接口 502 | 后端还没起完（首次要导入 1200+ 道题）。等 1 分钟；还不行看 backend 日志 |
| 登录后报「API Key 解密失败」 | 换过 `APP_CRYPTO_KEY`。到「设置」页重新填一次 LLM Key 即可 |
| HTTPS 域名打不开，日志里证书申请失败 | 80 端口没放行、或域名还没解析到本机。先 `ping 你的域名` 确认解析 |
| 磁盘满了 | `docker image prune -a` 清旧镜像；`docker system df` 看占用 |

## 附录 A：服务器拉不到代码怎么办

国内服务器连 GitHub 有时不稳定。两个替代方案：

**方案一：用 Gitee 镜像**

在 Gitee 上导入这个仓库（Gitee 有「从 GitHub 导入」功能），然后 clone Gitee 的地址。

**方案二：从你本机上传**（最可靠）

在你自己的电脑上打包：

```bash
# 本机 Git Bash
cd /e/SelfFace
git archive --format=tar.gz -o /tmp/selfface.tar.gz HEAD
scp /tmp/selfface.tar.gz root@你的公网IP:/opt/
```

在服务器上解压：

```bash
mkdir -p /opt/selfface && tar xzf /opt/selfface.tar.gz -C /opt/selfface && cd /opt/selfface && ls
```

看到 `docker-compose.yml`、`deploy/`、`backend/` 这些就对了，然后继续跑部署脚本。

> 这样部署的目录**不是 git 仓库**，`deploy/update.sh` 会跳过拉取步骤。以后更新时重新上传覆盖即可。

## 附录 B：部署脚本都做了什么

想搞清楚发生了什么的话，`deploy/deploy.sh` 按顺序做这些事，每步都是幂等的（可以重复执行）：

1. 检查系统、内存、SELinux 状态
2. 内存 < 3.5G 且无 swap 时，创建 2GB swap 并写入 `/etc/fstab`
3. 没装 Docker 就用官方脚本装，已装则跳过
4. 写 `/etc/docker/daemon.json`：三个国内镜像源 + 容器日志限制（50MB × 3 份）
5. 生成 `.env`（已存在则**不覆盖**，保护已有密钥）并随机填充三个密钥
6. 补上 Maven / npm 国内镜像源
7. 内存 < 4G 时设 `COMPOSE_PARALLEL_LIMIT=1`，避免前后端同时构建把内存吃满
8. `docker compose up -d --build`
9. 轮询 `/api/health` 直到就绪（最多 7 分钟）
10. 打印访问地址和后续步骤

## 附录 C：端口与数据说明

| 端口 | 用途 | 对外 |
|---|---|---|
| 22 | SSH | 是 |
| 8090 | 前端入口（Nginx） | 阶段 ① ② 需要放行 |
| 80 / 443 | HTTPS 层（Caddy） | 阶段 ③ 放行 |
| 8081 | 后端 | **否**，只在容器内网 |
| 3306 | MySQL | **否**，只在容器内网 |

数据都存在 Docker 数据卷里（`mysql-data`），容器删了数据还在。要彻底清空的话：

```bash
docker compose down -v      # -v 会连数据卷一起删，⚠️ 不可恢复
```
